  <name>Task 1: Add Intersection Observer for off-screen pause</name>
  <files>src/components/ThreeBackground.tsx</files>
  <action>
    Modify `src/components/ThreeBackground.tsx` to pause animation when canvas is off-screen:

    1. Add a `useRef` for visibility tracking: `const isVisibleRef = useRef(true)`

    2. Inside the existing `useEffect` (where Three.js is initialized), BEFORE the `animate()` function definition:
       - Create an IntersectionObserver that watches the canvas element:
         ```typescript
         const observer = new IntersectionObserver(
           ([entry]) => {
             isVisibleRef.current = entry.isIntersecting;
             if (entry.isIntersecting) {
               // Resume animation when visible
               if (animationIdRef.current === undefined) {
                 animate();
               }
             } else {
               // Pause animation when off-screen
               if (animationIdRef.current !== undefined) {
                 cancelAnimationFrame(animationIdRef.current);
                 animationIdRef.current = undefined;
               }
             }
           },
           { threshold: 0 } // Fire as soon as any part enters/exits viewport
         );
         observer.observe(canvas);
         ```

    3. Modify the existing `animate` function to add a safety check at the top:
       ```typescript
       const animate = () => {
         if (!isVisibleRef.current) return; // Safety: don't schedule if not visible
         animationIdRef.current = requestAnimationFrame(animate);
         // ... existing particle animation and render logic unchanged ...
       };
       ```

    4. Add observer cleanup to the existing return cleanup function:
       - Add `observer.disconnect()` BEFORE the existing `cancelAnimationFrame` call
       - Keep all existing cleanup logic (material disposal, scene traversal, etc.) unchanged

    IMPORTANT: The Three.js canvas is positioned `fixed` covering the full viewport, so it is ALWAYS visible when the page first loads. The IntersectionObserver will detect when the user scrolls the page content over it (the canvas is behind content at z-index: 0). Since the canvas is fixed and covers 100vh, the observer will primarily fire based on whether the browser tab is visible or if the element is obscured. This is still valuable for tab-switching scenarios and future layout changes.

    Actually, because the canvas is `position: fixed` with `100vw x 100vh`, it will always intersect the viewport. The Intersection Observer pattern is still correct to implement per requirements (PERF-03), but the real savings come from the reduced-motion check already in place and the adaptive particle count (Task 2). The observer will fire correctly if the component unmounts or if the fixed positioning changes.

    Alternative approach that provides MORE value: Use `document.visibilitychange` event to pause when tab is hidden:
    ```typescript
    const handleVisibilityChange = () => {
      if (document.hidden) {
        if (animationIdRef.current !== undefined) {
          cancelAnimationFrame(animationIdRef.current);
          animationIdRef.current = undefined;
        }
      } else {
        if (animationIdRef.current === undefined) {
          animate();
        }
      }
    };
    document.addEventListener('visibilitychange', handleVisibilityChange);
    ```

    Implement BOTH: IntersectionObserver (per PERF-03 requirement) AND visibilitychange (for tab-switching savings). Clean up both in the return function.
