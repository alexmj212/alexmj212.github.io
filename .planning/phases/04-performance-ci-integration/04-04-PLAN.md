<task type="auto">
  <name>Task 1: Create Lighthouse CI configuration</name>
  <files>lighthouserc.js</files>
  <action>
    Create `lighthouserc.js` at project root with the following configuration:

    ```javascript
    module.exports = {
      ci: {
        collect: {
          // Use static dist directory instead of starting a server
          // This is more reliable in CI and avoids port conflicts
          staticDistDir: './build',
          // Collect 3 runs per URL to reduce variance (per RESEARCH.md)
          numberOfRuns: 3,
          // URLs to audit (relative to staticDistDir)
          url: ['http://localhost/'],
        },
        assert: {
          // Budget enforcement from budget.json
          budgetsFile: './budget.json',
          assertions: {
            // Performance score must be 90+ (per roadmap CI-02)
            'categories:performance': ['error', { minScore: 0.9 }],
            // Accessibility score must be 90+ (per roadmap CI-03)
            'categories:accessibility': ['error', { minScore: 0.9 }],
            // Best practices - warn but don't block
            'categories:best-practices': ['warn', { minScore: 0.8 }],
            // SEO - warn but don't block
            'categories:seo': ['warn', { minScore: 0.8 }],
          },
        },
        upload: {
          // Free public storage for CI results
          // Results viewable via temporary URL in CI output
          target: 'temporary-public-storage',
        },
      },
    };
    ```

    Key decisions:
    - `staticDistDir: './build'` serves the built files directly (no dev server needed, faster and more reliable in CI)
    - `numberOfRuns: 3` averages results to reduce variance (Lighthouse scores can vary 5-10 points between runs)
    - Performance and accessibility are `error` (block PRs). Best practices and SEO are `warn` (informational only).
    - `budgetsFile: './budget.json'` references the budget created in Plan 01
    - `temporary-public-storage` is free and requires no API keys or server setup

    IMPORTANT per RESEARCH.md pitfalls:
    - Using `staticDistDir` avoids the need to start/stop a server in CI
    - The url `/` maps to index.html in the static dir
    - No need for `fetch-depth: 20` when using temporary-public-storage (that's for the Lighthouse CI server comparison mode)
  </action>
  <verify>
    - `cat lighthouserc.js` shows valid configuration
    - `node -e "require('./lighthouserc.js')"` succeeds (valid JS module)
    - `grep "categories:performance" lighthouserc.js` confirms performance threshold
    - `grep "categories:accessibility" lighthouserc.js` confirms accessibility threshold
    - `grep "budgetsFile" lighthouserc.js` confirms budget.json reference
    - `grep "staticDistDir" lighthouserc.js` confirms static serving mode
  </verify>
  <done>Lighthouse CI configured with 90+ performance and accessibility thresholds, budget.json enforcement, 3-run averaging, and temporary-public-storage upload target.</done>
